## What this means

The Phase-3 constraint specification (`phase3/perturbation_constraints.py`) marks
certain features as **immutable** — they must never be modified by a perturbation.
The Phase-4 perturbation script (`phase4/phase4_perturbation.py`) perturbed those
same features anyway, creating an **inconsistency** between the two phases.

This report quantifies exactly how many rows in the existing `results/phase4/` files
were generated by perturbing features that the project ontology treats as immutable.
Those rows **cannot be used as final Phase-4 evidence** and must not appear in the
Stage 2 results.
